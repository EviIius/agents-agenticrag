# Host revision after the first failed pilot

The baseline v5 full pilot failed: 5/25 Web cases, incomplete Library facts and
citations, and excessive time to a validated answer. It is retained unchanged.
Do not spend a candidate pair or repeated inference qualifying that failed
contract. Its first-pilot failure is the stop condition, not an invitation to
retry the same prompts. The initial v4 import failure also remains archived.

The v6 revision changes host behavior only; its selection prompt remains byte
identical. Re-render the retained v5 selections with zero new model calls:

- Rejection means the host cannot substantiate an answer. It does not establish
  that the original sources lack the fact. Keep source snapshots inspectable.
- Certain explicit English questions about an unidentified speaker's personal
  facts require clarification. Do not assign an unrelated public author's
  experience to “I” or “we.” The scoped grammar check excludes quoted material
  and advice/how-to wording. It is conservative and incomplete, not an actor
  identity resolver or a general semantic verifier. A named subject is not
  automatically verified either. This needs broader evaluation before release.
- Partial excerpts explicitly do not establish a complete answer. A valid unit
  still carries no claim of verified truth, relevance or completeness.

Freeze source and replay inputs before execution. Report the personal-subject
correction separately from unchanged coverage and latency failures. The replay
does not count as a matched model evaluation, repeated consistency test, or
passing Web/Library qualification. No 8B, Research, deployment or default switch.
