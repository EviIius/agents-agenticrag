# Validator review: methodology and structure (28 Sep 2026)

**Roles.** Codex builds, Claude validates and advises, and Jake decides. Claude doesn't edit the code.

**What I reviewed.** The working tree on Jake's Mac as of 01:48 UTC on 29 Sep. The checksums of the nine core modules matched the copy I tested.

**How I checked.**

- Read every doc in `docs/`, plus the README.
- Read the core modules.
- Ran the test suite: 125 passed, 1 skipped (Postgres).
- Reproduced each bug below in a sandbox.
- Ran the live router against the real `.data/workbench-evaluation.json`.
- Compared everything with the design brief, `Local_Agents_and_Agentic_RAG.pdf`.

## Verdict

**The architecture is sound.** It is more disciplined than most personal RAG projects:

- The model only proposes; host code validates and acts.
- Sources are immutable, and the host builds citations.
- Agents run under hard budgets.
- Fixed RAG stays the default until another mode proves itself.

Keep all of that.

**The measuring stick is the problem.** Three things are wrong with it:

- The evaluation can't see retrieval.
- Automatic model routing acts on noise.
- Recent fixes were tuned against the same 24 questions they're scored on.

So Codex is optimising against a toy, and the code has started to collect patches that fit the test set. **Stop adding capabilities until evaluation v3 exists.**

## What's sound (keep)

1. **The host owns authority.**
   - Each agent step is a schema-validated proposal.
   - The host checks the arguments, applies the collection and scope, allows read-only tools only, and rejects invented citations.
   - This is the right design. Most agent frameworks get it wrong.
2. **Provenance.**
   - Source versions are immutable, with hashes of the original and parsed text.
   - Citation offsets and metadata are built by the host, never by the model.
3. **Fixed RAG first.** Agentic mode must earn its extra cost, which matches the design brief.
4. **A plain Python state machine instead of LangGraph.** This is the right call at this scale, and `architecture.md` argues it well.
5. **An honest experiment journal.**
   - Each run writes a `started` record before it runs and a `completed` or `failed` record after.
   - Failed runs stay in the metric denominators.
   - The docs say plainly that substring matching isn't correctness.
6. **Operations basics.**
   - Durable runs, marked `interrupted` after a restart.
   - Backups use SQLite's online backup, with checksums and a tested restore.
7. **Portability.**
   - OpenAI-compatible providers support three structured-output modes.
   - There's a model contract check.
   - This is what makes "use it anywhere" real.

## Criticism, ranked by impact

### P0-1: the evaluation corpus is too small to test retrieval, or the agent

- **The corpus is tiny.** The evaluation corpus is 4 files totalling 4,662 bytes, which chunk into **7 chunks**. The retriever returns up to 8 (`retrieval.py:19`), so every question receives the entire corpus.
- **Evidence recall has never been measured.** No case in v1 or v2 has `required_chunk_ids`, so `evidence_recall` is `null` in every report.
- **Whole layers are untested.** Nobody has tested hybrid search, RRF, chunking, embeddings, the reranker decision or Agentic's search-again loop.
- **"Fixed is as good as Agentic" is built into this setup.** The agent's job is to recover evidence the first search missed, and here the first search misses nothing.
- **The latency numbers won't hold.** Fixed's 1.28 s mean comes from prompts of roughly 1,000–1,500 tokens. Real evidence packs are up to 8,000 tokens and will be much slower on local models.
- **The app has never seen a real library.** The live workbench corpus (`.data/corpus.db`) is one document in 10 chunks.
- **Agentic and Supervisor have barely been evaluated.** They have never run on v2; they've only been measured on the one-question smoke test.

**Fix: build evaluation v3.**

- **Corpus:** 100–300 real documents and at least 2,000 chunks. Include:
  - long PDFs;
  - tables;
  - near-duplicates;
  - two versions of the same document.
- **Questions:** at least 150, each with gold evidence written as *quote + document*, not chunk IDs, so re-chunking doesn't invalidate them.
- **Splits:** a dev split and a locked split.
- **Multi-hop cases:** include cases where the second hop shares no vocabulary with the question. That's the only place Agentic can win.

### P0-2: automatic routing is on by default and acts on noise

- **It's on by default.** Auto is on unless you turn it off (`ui/app.js:8`).
- **Its data is thin.** The router reads `workbench-evaluation.json`: v1, 8 questions, 1 repeat, 2 unanswerable cases.
- **I ran `choose_model` against that live report.** Every Fixed question routes to **Llama 3.3 70B** (22.4 s mean) rather than Qwen3 30B (2.1 s).
  - The margin is one answer case out of six and one abstention case out of two.
  - This contradicts the plan, which says Qwen 32K is the selected model.
  - This applies whenever the 70B is installed.
- **The formula is too simple.** Latency is only a tiebreaker, and there's no significance test.

**Fix:**

1. Turn Auto off by default now.
2. Only route on locked-split results with enough cases: at least 30 answerable and 10 unanswerable per group.
3. Require a paired-bootstrap confidence interval that excludes zero.
4. Add an explicit latency cost.

### P1-3: fixes are being tuned to the test set

- **The same questions were re-run over and over.** `.data` holds 12 evaluation runs from about 21 minutes on the evening of 28 Sep, all drawn from the same 24 questions. Five were full v2 reruns: qwen, recheck, repeat, final and validated. Six were 1–4-question subsets: calories-check, citations-check, citation-repair ×2, one-source-collapse and one-source-markers. The twelfth was the Gemma pass. That's a fix-and-rerun loop on one set.
- **The code contains the sample corpus's own words.** `workflows.py:299` hard-codes `{"sheet","pan","one","pot","chicken",...}`, the words in the sample corpus file names.
- **Some fixes patch a single output.** `workflows.py:236` is an English regex that forces abstention when an answer starts "The evidence does not state…". It patches one Gemma output.
- **So v2's 100% is dev-set accuracy.** The pilot doc already warns that 100% doesn't mean the claims are supported.

**Fix, as three standing rules:**

1. The locked split is never inspected case by case.
2. No corpus-specific words in the code.
3. Every fix names the failure class it addresses and is scored on the locked split.

### P1-4: each mode has different guardrails, so make one answer gate

The numeric-grounding check (the "600 calories" fix) runs only in Fixed (`workflows.py:110`). Agentic and Supervisor don't have it. The two modes meant to be more careful have fewer deterministic checks.

**Fix:** add an `answer_gate.py` that every grounded mode's final answer passes through. It runs these checks in order:

1. Citation resolution.
2. Supporting-quote verification.
3. Numeric grounding.
4. Marker coverage.
5. Abstention consistency.

Each check emits an event. Then the gate is evaluated once, not three times.

### P1-5: claim support is the missing piece, and self-review isn't it

- **Resolution isn't support.** Citation resolution proves the chunk ID exists, not that it supports the sentence. `architecture.md` says this itself.
- **The reviewer is the author.** Agentic and Supervisor are reviewed by the same model that wrote the answer, so the blind spots overlap.
- **Fixed has no claim check at all.** "Parchment prevents sticking" passed, although the note only says parchment makes cleanup easier.

**Cheapest deterministic fix: quote-backed citations** (DATA-CONTRACT B8 already asks for supporting quotes):

- The model returns a short verbatim quote for each citation.
- The host checks that the quote appears in the cited chunk, ignoring case and whitespace.
- If the quote can't be verified, the host drops the claim or makes one repair attempt.
- This needs no extra model, and it also drives the evidence-card highlight in the new UI.

**Second tier:** Qwen3-Reranker-0.6B, the design brief's pick, doing two jobs:

- reranking retrieval candidates;
- scoring each (sentence, cited chunk) pair for support.

That's one small local model for both jobs.

### P1-6: bugs I reproduced

a. **Numbered lists trip the numeric check.**
   - An answer written as "1. … 4." fails with *"Answer includes 4, which is absent from cited evidence"* when the source has no "4".
   - The result is a wasted repair call and possibly a false abstention.

b. **`repair_markers` strips bracketed numbers anywhere, code included** (`citation_markers.py:8`). `` `x = arr[3]` `` becomes `` `x = arr` `` when there are fewer than 3 citations.

c. **`_repair_explicit_source_markers` flattens formatting.** It rejoins sentences with a space (`workflows.py:327`), so lists and paragraphs collapse into one line.

d. **A malformed plan or review fails the whole Agentic run.**
   - A bad plan response raises out of `run()` (`agent.py:252`). It should fall back to a single obligation.
   - A bad review response does the same (`agent.py:340`). It should count as a rejected review.
   - Small local models do produce these malformed responses.

e. **Agentic makes a wasted planning call on simple questions.**
   - The planning call runs before the single-fact check (`agent.py:244` vs `:253`).
   - For single-fact questions the plan's obligations are then thrown away, so the most common question type pays for one extra model call.
   - The plan also picks skills, so skip the call only when no skills are available.

### P2-7: "access scopes" are filters the browser chooses, not permissions

- **The client picks its own scopes.** The browser sends them (`server.py:586`, `:661`), and there's no authentication.
- **The architecture doc overstates this.** Its invariant 1 says "the authenticated application supplies scopes", which isn't true yet. Any device on the tailnet can ask for any scope.
- **For a single user that's fine, if it's labelled honestly.**

**To make it real:**

- Tailscale Serve adds identity headers (`Tailscale-User-Login`) to proxied requests.
- Check those against an owner allowlist and map scopes on the server.
- Trust the headers only because the app binds to loopback and only Serve proxies to it.

**Also cheap: a Host-header allowlist on every request.**

- Today GET requests have no Origin or Host check.
- So a malicious page opened on the Mac mini could use DNS rebinding to read `/api/v1/sources`.

### P2-8: SQLite vector search won't scale far

- **Every search is a full scan in pure Python.** Each query loads every vector as JSON and computes cosine similarity in Python (`store.py:395`).
- **Measured cost:** 5,000 chunks × 1,024 dims took **2.2 s per search** in my sandbox. The Mac mini is faster, but the cost still grows linearly with the corpus.
- **Agentic multiplies it**, because it runs several searches per question.

**Fix:** the Postgres + pgvector adapter already exists. Set the switch point (roughly 2,000–3,000 chunks), or store float32 blobs instead of JSON.

### P2-9: retrieval improvements to try once v3 exists (they can't be measured before)

- **Contextual chunk headers.** Embed "Document title › Section" plus the chunk text. Today only the raw text is embedded (`ingestion.py:432`).
- **Section-aware chunking.** Today chunks are fixed 1,200-character windows that cross section boundaries.
- **Wire in the reranker.** The protocol exists (`retrieval.py:12`) but is never instantiated.
- **Adjacent-chunk expansion** (milestone 4 of the plan).

The plan's rule "add a reranker only after measuring a gain" is correct, but it's blocked today because the evaluation can't show any gain.

### P3-10: code structure

- **Two large files.** `server.py` is 1,254 lines in one handler full of if-chains. `app.js` is 2,555 lines.
- **The CSS is layered.** `design-v2.css` sits on top of `styles.css`.
- **This is fine for now.** Split routes into modules and `app.js` into ES modules (still no build step) during design Phase 5.
- **Supervisor is drifting in scope.**
  - Its hard-coded specialists include `ad_strategist`.
  - It picks specialists with English keyword regexes (`supervisor.py` `_select_assignments`).
  - For a general-purpose tool this is scope creep. Freeze Supervisor features until v3 shows a gain on multi-part questions.
